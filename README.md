- [1](https://t.me/c/3309935762/54)

Реализовать базовый сервис-заметница:
* Makefile (либо Taskfile на ваше усмотрение) для сборки, запуска, установки зависимостей.
* proto файл с одним сервисом и несколькими rpc: Получение списка заметок, получение одной заметки, добавление/удаление.
* реализация сервера (клиент опционально) выбор подхода для хранения данных на ваше усмотрение, можно использовать in_memory. Но лучше следовать ЧА (Чистая Архитектура) и не писать реализацию бизнес логики в хэндлерах.

  Домашнее задание:

#### Задание 1: Интерцепторы (Middleware)

Необходимо реализовать два серверных Unary-интерцептора и подключить их через grpc.ChainUnaryInterceptor.

Logger Interceptor:

- Должен перехватывать запрос
- Логировать начало запроса (Method name)
- Замерять время выполнения хендлера
- Логировать конец запроса (статус ответа + затраченное время)

💡 Совет: используйте time.Now() и time.Since()

Auth Interceptor:

- Должен извлекать метадату из контекста (`metadata.FromIncomingContext`)
- Проверять наличие ключа authorization

Логика:

- Если ключа нет или токен не валиден (например, хардкод Bearer my-secret-token`), возвращать ошибку со статусом `Unauthenticated
- Если токен валиден, пропускать запрос дальше к хендлеру

#### Задание 2: Конфигурация сервера

Вместо дефолтного запуска сервера grpc.NewServer() добавьте опции (`grpc.ServerOption`) для управления соединениями, чтобы защитить сервер от зависших коннектов и перегрузки.

Настройте следующие параметры (значения можно взять примерные, главное наличие конфигурации):

- MaxConcurrentStreams: ограничьте количество одновременных стримов (например, 10-50)
- KeepAlive: настройте параметры Time (время между пингами) и Timeout (время ожидания ответа), чтобы разрывать мёртвые соединения

#### Задание 3: Валидация (Protovalidate)

Внедрите валидацию на уровне .proto файла, чтобы не писать проверки if len(req.Title) == 0 в Go-коде.

Подключите зависимость [`buf.build/bufbuild/protovalidate`](http://buf.build/bufbuild/protovalidate) (или protoc-gen-validate, если используете старый стек, но в лекции рекомендовали современный подход).

Модифицируйте метод CreateNote (или аналогичный):

- Поле title: обязательное, минимальная длина 5 символов, максимальная 255
- Поле content: обязательное, минимальная длина 10 символов
- Поле email (если есть): должно соответствовать формату email

Сгенерируйте код (`easyp generate` или `protoc`).

Вставьте интерцептор валидации или вызовите валидатор внутри хендлера (как было показано в лекции: `validator.Validate(req)`).

#### Задание 4: Rich Error Handling (Детализация ошибок)

Измените возврат ошибок в одном из методов (например, `GetNote`).

Вместо простого status.Errorf(codes.NotFound, "note not found") реализуйте возврат ошибки с деталями (`WithDetails`).

Создайте (или используйте существующий) message в proto-файле для описания ошибки (например, ErrorDetails с полем reason или `internal_error_code`).

Сценарий:

- Если заметка не найдена, верните статус NotFound
- В Details положите сообщение: "Note with ID {id} was searched but not found in DB"

*(Опционально)* Напишите в клиенте код, который проверяет: если пришла ошибка, попробуй достать из неё Details и вывести пользователю красивое сообщение.
